# QE-490 — Transpose the trial matrix to time-major before CSCV so the live PBO gate partitions time, not the trial axis  *(R5 — panel review 2026-07-31, follow-up to QE-478, P1)*

> **Status:** Done (this PR) — [panel review](../../reviews/panel-review-2026-07-31.md) · [PR #182 review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md)

`Phase: Review R5 (panel review — PR #182 review)` · `Area: validation / cli (train)` · `Depends on / relates to: QE-478 (raised CSCV_BLOCKS), QE-131 (CSCV/PBO)`

**Why.** QE-478 raised `CSCV_BLOCKS` `2 → 8` and its docstring claimed this makes "the live `max_pbo = 0.5` gate a real threshold." The PR-#182 review panel (finding R4.1, CONFIRMED major) showed that claim is **false in production**: `validation::assess` calls `pbo_cscv(stats.trial_returns, …)` (`crates/validation/src/lib.rs:151`), but `trial_returns` is **strategy-major** (`trial_returns[k]` = trial `k`'s series, `[strategy][time]`), while `pbo_cscv` consumes a **time-major** `[time][strategy]` matrix and splits `matrix.len()` — the **time** axis (`crates/validation/src/pbo.rs:22-45`). Fed a strategy-major matrix, `pbo_cscv` split the `≤ N`-strategy axis into `S` blocks (with a ≤10-strategy pool, ~1 strategy/block, and the ≤8-strategy fallback erroring out), so the sealed `RobustnessReport.pbo` was a **meaningless estimator** and the smooth 70-partition behaviour existed only in `pbo_cscv`'s own (correctly time-major) unit test. The transpose was **pre-existing** — the GP path already does it right: `uncensored_pbo` (`crates/wfo/src/gp/deflation.rs:159-171`) transposes `population[k][t]` to time-major before CSCV. `assess` was the sole caller that forgot.

**Scope / requirements.**
- **Transpose at the `assess` PBO call.** Add `columns_to_time_major` in `crates/validation/src/pbo.rs` (strategy-major `[k][t]` → time-major `[t][k]`, min-length truncation, mirroring `uncensored_pbo`), and apply it at `crates/validation/src/lib.rs:151` so `S` partitions the **time** axis. SPA (`excess_over_benchmark`) and DSR (scalar `trial_variance`) are strategy-wise and stay **unchanged**.
- **Fix the thin-run guard.** In `assess_robustness` (`crates/cli/src/jobs/train.rs`) the guard `pool.len() < CSCV_BLOCKS` keyed off the **trial count** (the buggy powering dimension). Re-key it to the correct dimensions: fail closed to the conservative report unless there are **≥ 2 trials** (to rank an IS-best against peers) **and each series is ≥ `CSCV_BLOCKS` bars** (enough time to form the blocks).
- **Correct the docstring.** Rewrite the `CSCV_BLOCKS` docstring to state that CSCV partitions the time axis (matrix transposed before CSCV) and describe the corrected guard — no false "real threshold" claim without the orientation being right.

**Out of scope.** `pbo_cscv`'s time-major contract and its unit tests (already correct). The GP/evolve `uncensored_pbo` path (already transposes). The conjoined CPCV(S=6) gate and the fail-closed G1 conjunction (untouched). No change to `VintageStats` field semantics — only the orientation handed to `pbo_cscv`.

**Acceptance criteria.**
- `assess` transposes `trial_returns` to time-major before `pbo_cscv`; a test (`assess_splits_the_time_axis_not_the_trial_axis`) with **fewer trials than blocks but a long series** returns `Ok` — it would `EmptyMatrix`-error on the pre-fix (untransposed) call, proving CSCV now splits **time**.
- The thin-run guard fails closed on short series (`thin_time_series_falls_back_to_conservative_pbo`): a 10-trial pool with series length `CSCV_BLOCKS - 1` yields the conservative `pbo = 1.0`.
- On a real train (≥ 2 trials, window ≫ 8 bars) the sealed `pbo` is a genuine `k/70` fraction, not the conservative sentinel — the `max_pbo = 0.5` gate becomes a real threshold.
- Full suite green (`fmt`, `clippy -D warnings`, `test --workspace`, firewall, `deny`); the PBO value change moves no committed golden and does not alter the integration test's (unasserted) promotion outcome.
