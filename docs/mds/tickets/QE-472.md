# QE-472 — LLM formula ideation: `qe ideate` proposes candidate `Expr` formulas into the GP pool, every canonical candidate counted in the trial ledger, sealed only through the existing DeflationGate  *(R4 — agentic-AI)*

> **Status:** Todo — [design discussion](../../afml-gap-analysis.md) · [backlog index](../../backlog.md#agentic-ai) · [spec](../../specs.md)

`Phase: Review R4 (agentic-AI)` · `Area: cli / signal / formula-pool / wfo / (new) llm-client` · `Depends on: QE-471 (LLM client plumbing), QE-451 (GP evolve engine + trial ledger), QE-450 (Expr grammar), QE-454 (production-seal governance)`

**Why.** The engine's alpha search is a genetic-programming / MAP-Elites process that mutates `Expr` indicator formulas (`crates/signal/src/indicator/expr.rs:184`) over the frozen catalogue (`CatalogueIdentity`, `crates/signal/src/feature.rs:115`), evaluates them, and seals only those that clear the deflation gate into a `FormulaPool`. This ticket adds a **new source of candidate formulas** — an LLM that proposes `Expr` trees given the catalogue and grammar — while leaving the entire evaluation, deflation, and seal machinery **untouched**. Claude widens the search *intake*; the existing firewall (`FormulaGateEvidence`/`DeflationGate`/PBO+DSR) remains the sole arbiter of what ships.

**The one load-bearing invariant.** The engine's crown jewel is its false-discovery control: DSR and PBO are only valid if **every hypothesis ever scored is counted** in the trial basis (`gp_trial_basis` / `effective_trials`, `crates/wfo/src/gp/deflation.rs:30-40`; the "every evaluated formula counts toward N" discipline). An LLM that proposes many candidates is, by construction, a multiple-testing amplifier. Therefore: **every distinct canonical LLM-proposed formula MUST increment the trial ledger exactly as a GP-mutated formula does.** A design that lets AI-generated candidates bypass the ledger silently inflates DSR and destroys the property that makes the whole engine trustworthy. This invariant is the reason the ticket exists as much as the feature is.

**Engineering reality.** Reuses the feature-gated `llm` client from QE-471 (raw HTTPS `POST /v1/messages`, `reqwest`, model `claude-opus-5` by default, `ANTHROPIC_API_KEY` from env, streamed, `stop_reason`-aware). The ideation job is **offline/batch** and produces *candidates* fed into the existing offline GP pipeline — it is **never** in the live path and never in the QE-006 deterministic core (the LLM call is non-deterministic; only its *output candidates*, once parsed and canonicalised, enter the deterministic evaluation, which stays byte-reproducible).

**Scope / requirements.**
- **`qe ideate` job.** New `crates/cli/src/jobs/ideate.rs` + subcommand. It prompts Claude with the current indicator catalogue (`CatalogueIdentity::current()`) and the `Expr` grammar, requesting N candidate formulas via **structured outputs** (`output_config.format` with a JSON schema mirroring `Expr`) so candidates arrive as typed JSON, not prose. `--n`, `--model` (default `claude-opus-5`), and a `--seed-context` (optional: recent pool formulas / IC results to steer ideation) flags.
- **Strict parse-and-validate into `Expr`.** Each proposed JSON candidate is deserialised and validated into a legal `Expr` against the **current** `CatalogueIdentity`. Anything that references an unknown indicator, violates the grammar, or fails type/shape checks is **dropped here with a logged reason** — the LLM cannot invent operators or reach outside the frozen catalogue. Log the accept/drop counts (no silent truncation).
- **Canonicalise, dedupe, and COUNT.** Canonicalise each surviving candidate and dedupe against the pool (`FormulaPoolContent::formula_hashes`, `crates/formula-pool/src/lib.rs:257`) and within the batch. **Every distinct canonical candidate increments the GP trial ledger** (`gp_trial_basis`) — this is asserted, not assumed. Duplicates of already-scored formulas are counted once (the ledger is over-canonical-formulas-ever-scored, per QE-451).
- **Feed the existing GP evaluation + seal path unchanged.** Surviving, counted candidates are evaluated by the existing GP evaluator producing `FormulaGateEvidence` (`.passes()`, `lib.rs:143`); only formulas clearing `DeflationGate` (PBO primary + DSR floor) are eligible for the pool via the existing `FormulaPool::seal` / `assert_production_eligible` (`lib.rs:248,281`). **No gate, threshold, or seal predicate is modified.** Production-seal governance (QE-454, `seal_allowed`) applies unchanged — LLM-sourced formulas are subject to the identical structural barriers.
- **Provenance: mark LLM-sourced candidates in lineage.** Record in the pool/vintage lineage that a candidate's *origin* was `llm` (model id + prompt/catalogue hash), so a sealed formula's provenance shows whether it came from GP mutation or LLM ideation. This is an audit field on lineage, not a gate input — the gate treats both origins identically.
- **Determinism boundary.** The LLM call and candidate list are outside the deterministic harness; once candidates are parsed + canonicalised, evaluation is the existing byte-reproducible path. The ideation batch (which candidates were proposed) is logged/persisted for reproducibility of the *research step*, but a re-run need not reproduce the LLM's stochastic output — only the evaluation of a given candidate set must be deterministic.

**Out of scope.** Any change to `DeflationGate`, `FormulaGateEvidence`, the seal predicate, `gp_trial_basis` computation, or catalogue freezing (QE-451/QE-454 own those). An **outer loop that regenerates candidates based on which ones passed** — that is the explicitly-rejected overfitting pattern (QE-455 guardrail) and must not be built here; ideation is a one-shot intake per invocation, not a best-of-N optimiser over the gate. Live/paper-path LLM calls. Letting the LLM see held-out / G1 data (it sees the catalogue and grammar, never the holdout).

**Acceptance criteria.**
- `qe ideate --n K` calls Claude, parses candidates via structured outputs, and reports accepted/dropped counts with drop reasons; invalid/out-of-catalogue candidates are dropped before evaluation.
- **Ledger invariant test (the critical one):** a batch of K distinct canonical candidates increases the trial basis by exactly K new entries (duplicates of already-scored formulas add zero); a test proves `gp_trial_basis` after ideation equals the pre-existing count plus distinct-new-canonical count. A candidate that reaches evaluation without being counted is a test failure.
- Surviving candidates flow through the **unmodified** GP evaluation + `DeflationGate` + seal path; no gate/threshold/seal-predicate diff (firewall/dependency test stays green), and QE-454 `seal_allowed` governs LLM-sourced formulas identically.
- Sealed formulas' lineage records `origin = llm` (model id + catalogue/prompt hash) as an audit field, not a gate input.
- The LLM never receives holdout/G1 data; a test asserts the prompt payload contains only catalogue + grammar (+ optional `--seed-context` of *already-sealed* pool data), never held-out returns.
- `llm` feature off by default; deterministic core and QE-006 harness unchanged; evaluation of a fixed candidate set is byte-reproducible.
- No outer regenerate-on-pass loop exists (reviewer-checkable): ideation is one-shot per invocation.
