# QE-497 — Wire open-interest + premium ingest into the historical fetch, reviving the dead flow indicators (richer factor breadth)  *(R6 — fleet diagnosis 2026-08-01, P1)*

> **Status:** Todo — [G1-hunt diagnosis](../../reviews/) · [backlog index](../../backlog.md)

`Phase: Review R6 (real-data edge experiment)` · `Area: ingest / storage / cli (features)` · `Depends on / relates to: QE-107 (flow indicators), QE-463 (klines-only uncalibrated slice), QE-495 (funding join)`

**Why.** The G1-hunt diagnosis (81 runs, 0 passes) identified **factor breadth**, not data quantity or search size, as a binding constraint: the store is klines-only, so of the four funding/premium/OI **flow indicators already in the catalogue**, only the two funding-based ones (`funding_state`, `funding_avg_8`) carry data — **`premium_state` and `oi_roc_10` are dead** (`crates/signal/src/indicator/flow.rs`), because `qe ingest` never populates premium or open-interest. The infrastructure is *already there*: the REST decoders exist and are tested (`RestEndpoint::OpenInterestHist` → `/futures/data/openInterestHist`, `crates/ingest/src/rest.rs:26-49`; premium-index plumbing through `fuse.rs`/`canonical.rs`), and storage has `put_premium`/`scan_premium` (`crates/storage/src/store.rs:419`). But the historical fetch returns empty premium/OI, the ingest job hardcodes `open_interest: Vec::new()` (`crates/cli/src/jobs/ingest.rs:257,362`), and `to_decision_bars` sets `Sample.open_interest = None` and joins premium from an empty map (`crates/cli/src/jobs/features.rs`). Wiring the existing decoders end-to-end revives a *different signal class* (positioning / basis / carry) — the diagnosed missing factors — at moderate cost.

**Scope / requirements.**
- **Fetch:** wire the existing `OpenInterestHist` and premium-index (`premiumIndexKlines`) endpoint decoders into the historical fetch path so a real `qe ingest` retrieves open-interest and premium alongside klines + funding. Keep them **optional/degrade-gracefully** — a symbol/venue lacking one series ingests the rest (fail-open on a *missing optional factor*, never fail-closed the whole ingest).
- **Store:** add `put_open_interest` / `scan_open_interest` to `MarketStore` (mirroring `put_premium`/`scan_premium`; new `DB_OPEN_INTEREST` db). Premium already has a store path.
- **Join:** in `to_decision_bars`, populate `Sample.open_interest` and `Sample.premium` from the scanned series (exact-on-grid for premium/OI klines — no jitter class like funding; OI is per-period). Keep the QE-495 funding join unchanged.
- **Provenance / calibration:** update the QE-463 `Uncalibrated` klines-only labelling honestly — a store with real premium/OI is richer but still not full execution-calibration; do not overclaim tradability. Do not silently flip the liquidity flag.
- **Determinism:** ingest stays deterministic per the QE-006 harness; the added series are content-addressed like bars/funding.

**Out of scope.** New indicators beyond reviving `oi_roc_10`/`premium_state` (they already exist). Mark-price / index-price series (separate factor). Execution calibration (QE-440/447). The multi-symbol universe (QE-498). Any gate/threshold change.

**Acceptance criteria.**
- A real `qe ingest --features http` over a Binance window populates **nonzero open-interest and premium** counts (verified against the live API — the report line stops saying "0 premium").
- `MarketStore::put_open_interest`/`scan_open_interest` round-trip; a store-level test covers OI + premium persistence and retrieval.
- After ingest, a train over that window produces decision bars whose `Sample.open_interest`/`Sample.premium` are populated, so `oi_roc_10` and `premium_state` produce **non-constant** features (a test asserts the two previously-dead indicators now vary).
- A symbol missing an optional series still ingests bars+funding (graceful degradation test).
- Full suite green (`fmt`/`clippy -D warnings`/`test --workspace`/firewall/`deny`); no new non-allowlisted crate.
