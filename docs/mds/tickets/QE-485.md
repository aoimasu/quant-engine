# QE-485 — Commit bars and their provenance segment in ONE `wtxn` so a crash can never leave real bars permanently labelled `Unknown`  *(R5 — panel review 2026-07-31, P2)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: storage` · `Depends on / relates to: QE-464 (per-run provenance segments)`

**Why.** `put_bars_with_provenance` (`crates/storage/src/store.rs:271`) commits the bars and their provenance segments in **two separate write transactions**. The bar puts go through `self.put_bars(...)` (`store.rs:278`), which opens its own `wtxn` and commits at `store.rs:111`; the per-resolution `ProvenanceSegment` puts then open a *second* `wtxn` (`store.rs:280`) and commit at `store.rs:298`. A crash, panic, or process kill in the window between those two commits leaves the bars durably persisted with **no** provenance segment covering them. The provenance fold then reads those bars as `Provenance::Unknown` (and, mixed with tagged neighbours, `Mixed`). Because incremental ingest never re-fetches slots already covered by bars (`coverage_bounds`/`count_bars_in_range` short-circuit re-fetch), the mislabel is **permanent** — real market data is forever under-labelled and can be excluded from real-only training/eval sets. This fails *safe* (synthetic is never mislabelled as real, since synthetic bars are never written without their tag committing first) but it violates the fail-closed **atomicity** invariant: a bar and its origin must be all-or-nothing.

**Scope / requirements.**
- Inline the bar puts and the per-resolution provenance-segment puts into a **single** `wtxn` inside `put_bars_with_provenance`, committing exactly once. Replace the `self.put_bars(...)` call (`store.rs:278`) with the bar-put loop written into the *same* `wtxn` that writes the segments — preserve the exact bar key/value path (`bar_key`, `self.bars.put`) so bar identity and any snapshot-id-over-bar-bytes are byte-unchanged.
- Keep the existing per-resolution segment logic (`Resolution::ALL` loop, `first`/`last` from batch times, `ProvenanceSegment { end_ms, provenance, calibration }` keyed by `bar_key(instrument, resolution, first)`) exactly as-is — only the *transaction boundary* moves.
- Preserve the empty-batch no-op (an empty `bars` slice writes nothing and commits nothing).
- Leave `put_bars` (`store.rs:105`) untouched as the standalone untagged path; only the provenance-carrying entry point becomes atomic.

**Out of scope.** The provenance fold / `Unknown`/`Mixed` classification logic (`provenance_summary` and callers). Incremental-ingest re-fetch policy (QE-412 coverage machinery) — that stays a no-op over covered slots; this ticket only guarantees the tag is present the instant the bars are. The provenance index schema / `ProvenanceSegment` layout. Any change to `Resolution::ALL` iteration order.

**Acceptance criteria.**
- A test proves atomicity: after `put_bars_with_provenance`, a `(instrument, resolution)` pair that has stored bars **always** has a covering provenance segment — real bars are never observed as `Unknown`. Simulate the crash window by asserting there is no code path (single-txn structural assertion, or a fault-injection that aborts after the bar puts) that commits bars without their segment.
- A test that incremental ingest over already-covered slots is unaffected: re-invoking with an overlapping/identical batch does not corrupt bars or duplicate/mislabel segments, and the covered-slot re-fetch short-circuit still holds.
- Determinism: bar bytes and provenance-segment bytes are byte-identical to the pre-change two-txn path for the same input batch (the merge is a transaction-boundary change only; QE-006 harness green).
- No `VINTAGE_FORMAT_VERSION` / golden bump — this is a durability fix, not a sealed-schema change; confirm no golden diff.
