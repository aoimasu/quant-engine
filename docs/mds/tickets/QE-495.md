# QE-495 — Jitter-tolerant funding join: match real venue funding stamps to bars by nearest-hour, not exact millisecond  *(R6 — fleet run 2026-08-01, P0)*

> **Status:** Done (this PR) — [backlog index](../../backlog.md)

`Phase: Review R6 (real-data fleet run)` · `Area: cli (features / decision-bar assembly)` · `Depends on / relates to: QE-103 (funding ingest), QE-251 (decision bars), the funding-coverage gate (crates/cli/src/jobs/mod.rs:137)`

**Why.** `to_decision_bars` (`crates/cli/src/jobs/features.rs`) joined funding (and premium) samples to bars by **exact-millisecond** open-time equality (`funding_by_ms.get(&ms)`). Real Binance `fundingTime` stamps are not exactly on the hour: **151 of the 1098 BTCUSDT stamps in 2024 carry 1–3 ms of jitter** (e.g. `…08:00:00.001`) — measured directly against `fapi.binance.com/fapi/v1/fundingRate`. The exact-ms join silently dropped every jittered stamp, so funding coverage read ~84% and the **90% coverage gate refused to seal on every real-data train** (`funding coverage 84% … below the required 90%`). The synthetic path was unaffected (its stamps are generated exactly on-grid), which is why this only surfaced on real data. This blocked the entire fleet run until fixed.

**Scope / requirements.**
- Round each **sample** stamp to the nearest whole hour before building the join map (`round_to_hour_ms`, pure integer `(ms + 30min).div_euclid(1h) * 1h`). Bars open exactly on the hour and the funding grid is 8h, so ±30-min tolerance heals venue jitter with **zero** risk of a stamp colliding onto a different grid point. Deterministic (QE-006) — no float, no wall-clock.
- Apply to **funding only**. (Correction, PR#183 review R3.1: premium `premiumIndexKlines` are dense, exactly on the bar grid, and carry no jitter, so their exact-ms join was already correct — rounding premium would over-snap sub-hour samples onto the wrong bar and inject look-ahead. Funding is the sole jittery, sparse-grid factor.)

**Out of scope.** Changing the 90% coverage threshold or the coverage-expected computation (`funding_coverage`, train.rs:343) — the join was the defect, not the gate. Interpolating missing funding (a real gap must still fail closed).

**Acceptance criteria.**
- Unit test (`jittered_funding_stamps_round_onto_the_bar_grid`): identity on exact stamps; ±ms jitter in both directions snaps to the hour; adjacent grid points unaffected; a genuine half-hour offset rounds to its nearest hour (never a different 8h stamp). **[met]**
- A real-data train over a window with full Binance funding now clears the coverage gate and seals (verified: 2024 BTCUSDT 1h train reached the G1 gate instead of erroring at feature assembly).
- Synthetic-path output byte-identical (its stamps are already on-grid ⇒ rounding is a no-op).
- Integration test (`to_decision_bars_recovers_jittered_funding_and_leaves_a_genuine_gap_unfunded`, PR#183 review R6.2/R5.1): a stamp 1ms past the hour lands on its on-hour bar; a bar with no nearby stamp stays `None`; exactly one bar is funded — proving rounding heals jitter but never bridges a real gap or inflates coverage. **[met]**
