# QE-478 — Raise `CSCV_BLOCKS` from 2 to 8-10 so PBO is a smooth probability, not the degenerate {0, 0.5, 1} three-value estimator  *(R5 — panel review 2026-07-31, P1)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: cli (train/evolve) / validation / gate` · `Depends on / relates to: QE-437 (PBO gate), QE-469 (CPCV backstop)`

**Why.** The Probability of Backtest Overfitting is computed on `const CSCV_BLOCKS: usize = 2` — `crates/cli/src/jobs/train.rs:60` (and identically `crates/cli/src/jobs/evolve.rs:36`) — passed as `cscv_blocks: CSCV_BLOCKS` into the vintage stats at `train.rs:1473`. `crates/validation/src/pbo.rs:50` enumerates `combinations(blocks, blocks/2)` = `combinations(2, 1)` = exactly **two** balanced partitions, so PBO can only take the values `{0.0, 0.5, 1.0}`. The gate is `robustness.pbo.is_finite() && robustness.pbo < criteria.max_pbo` (`crates/gate/src/lib.rs:182`) with `DEFAULT_MAX_PBO = 0.5` (`gate/src/lib.rs:31`), so passing requires `pbo == 0.0` **exactly** — a coin-flip estimator on a live promotion gate. VERIFICATION (twice): the degenerate estimator is real and on a live gate, but it is **conservative** (strict), not lax — the two-block split can only over-reject — and the QE-469 CPCV(S=6) distribution gate is a conjoined backstop; hence P1 correctness of the estimator, not a promotion-bypass. It violates statistical honesty: a "probability of overfitting" that resolves to three points is not a probability.

**Scope / requirements.**
- **Raise `CSCV_BLOCKS` to 8-10** in both `crates/cli/src/jobs/train.rs:60` and `crates/cli/src/jobs/evolve.rs:36` (keep the two constants in lockstep). At `S = 10`, `C(10, 5) = 252` balanced partitions ⇒ PBO becomes a smooth fraction over 252 logits, matching the block-count rationale behind `DEFAULT_CPCV_BLOCKS = 6` (`train.rs:64`). Choose the value subject to per-block length limits on the trial series (each of `S` blocks must stay long enough for a meaningful per-block Sharpe over the train window).
- **Keep the thin-run fail-closed fallback intact.** The guard `if pool.len() < CSCV_BLOCKS { return conservative(); }` at `train.rs:1452` must still fire — with a larger `CSCV_BLOCKS` an under-powered pool falls back to the conservative (`pbo = 1.0`) verdict rather than computing PBO on too few strategies. Preserve `pbo_cscv`'s own `EmptyMatrix` fail-closed (`pbo.rs:39`).
- Re-baseline the affected goldens once, intentionally (the PBO value on existing fixtures will move).

**Out of scope.** The CPCV distribution / `DEFAULT_CPCV_BLOCKS` and its input series (QE-477/QE-479). The `DEFAULT_MAX_PBO = 0.5` threshold and the gate predicate at `gate/src/lib.rs:182` (this ticket changes the estimator resolution, not the ceiling). The `pbo_cscv` logit arithmetic in `pbo.rs`.

**Acceptance criteria.**
- `CSCV_BLOCKS >= 8` in both `train.rs` and `evolve.rs`; a test shows PBO can take more than three distinct values on a sufficient pool (e.g. a value strictly in `(0, 0.5)`), impossible under `S = 2`.
- The thin-run fallback still fails **closed**: a test with `pool.len() < CSCV_BLOCKS` returns the conservative report (`pbo = 1.0`), never a vacuous pass.
- Goldens regenerated intentionally (single, reviewed re-baseline of the PBO-bearing fixtures).
- Determinism preserved (QE-006): PBO is a deterministic function of the trial matrix; two runs byte-identical.
