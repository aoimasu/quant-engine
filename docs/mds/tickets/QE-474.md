# QE-474 — Fail closed when the base config file is absent: reject the load instead of returning a fully-defaulted config  *(R5 — panel review 2026-07-31, P0)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: config (+ cli/server boot)` · `Depends on / relates to: none`

**Why.** `Config::load` (`crates/config/src/lib.rs:42`) builds the layered figment with
`Figment::new().merge(Toml::file(base_path))` (`lib.rs:43`). Figment's `Toml::file` is
**missing-file-tolerant** — an absent path yields an empty dict rather than an error — and it is *not*
`Toml::file_exact`; there is no `base_path.exists()` guard anywhere in the load path. Every field
carries a serde default: instruments default to `BTCUSDT, ETHUSDT` (`crates/config/src/schema.rs:180`),
`StorageConfig` and `DeterminismConfig { seed: u64 }` derive `Default` so `seed = 0`
(`schema.rs:93-98`), and `validate()` passes on the pure-default config (the in-file test
`defaults_apply_for_minimal_config` demonstrates exactly this). The default target `config.toml` does
**not** exist in the tree — only the tracked `config.example.toml`, which `load` does not read by
default. So `Config::load(profile, "config.toml")` on a fresh checkout returns **Ok on a fully-defaulted
config**: a `RuntimeLive`/`RuntimeSim` process silently boots on the default universe and `seed = 0`
with no operator signal. This directly contradicts the crate's documented contract — "validated at load
(**fail-fast with field-level errors**)" (`lib.rs:6`) — and violates the **fail-closed** invariant: a
missing operator-supplied config must be a hard stop, not a silent default boot.

**Scope / requirements.**
- In `Config::load`, **fail closed on an absent base file** before merging. Either add a
  `if !base_path.exists() { return Err(ConfigError::Load(..)) }` guard at the top, or require the base
  layer — `Toml::file(base_path).required(true)` (or `file_exact`) — so a missing base surfaces as
  `ConfigError::Load`. Include the resolved path in the error string.
- **Preserve the optional profile overlay.** The `<stem>.<profile>.<ext>` overlay
  (`lib.rs:44-46`) must stay skip-if-absent — only the **base** layer becomes mandatory. Do not make the
  overlay or the `QE_`-env layer required.
- **Leave the no-filesystem paths intact.** `from_toml_str` (`lib.rs:60`) and the serde defaults remain
  for tests/embedding; this ticket changes only the on-disk `load` entry point.

**Out of scope.** The field-level `validate()` rules, the schema defaults themselves, the `QE_` env
override precedence, and the `content_hash` serialisation. Do not add a default-`config.toml` to the
tree — the fix is to reject its absence, not to paper over it.

**Acceptance criteria.**
- A test that `Config::load(profile, <nonexistent path>)` returns `Err(ConfigError::Load)` (not
  Ok-on-defaults), for each profile.
- A test that `Config::load` with a present base but **absent** profile overlay still succeeds (overlay
  skip behaviour preserved).
- `from_toml_str` continues to parse+validate an in-memory config unchanged (existing tests green).
- No change to `content_hash` output for any already-loadable config (determinism / QE-006 core
  untouched); no schema field added, so no golden/`VINTAGE_FORMAT_VERSION` movement.
