# QE-471 — LLM vintage narrator: read-only `qe explain <vintage-id>` that turns sealed `SealEvidence` into a plain-English writeup (feature-gated, off the deterministic core)  *(R4 — agentic-AI, build first)*

> **Status:** Todo — [design discussion](../../afml-gap-analysis.md) · [backlog index](../../backlog.md#agentic-ai) · [spec](../../specs.md)

`Phase: Review R4 (agentic-AI)` · `Area: cli / vintage / (new) llm-client` · `Depends on: QE-467 (persisted seal evidence); pairs with QE-468 (report honesty)`

**Why.** The sealed vintage already carries everything a human needs to understand a promotion — `SealEvidence { dsr, pbo, spa_pvalue, n_trials, realised_turnover, capacity_usd, cost_stress_net_min, uncensored_pbo, ic, fdr }` (`crates/vintage/src/lib.rs:62-92`) plus the full `ResearchProvenance { data_provenance, holdout_split, regime_composition, consultation_count, steer_delta }` (`crates/vintage/src/lib.rs:238-249`) — but it is a terse numeric block. A reader has to *already know* what a DSR of 0.97 against a PBO of 0.31 means. This ticket adds a **read-only** job that hands a sealed `VintageContent` to Claude and gets back a plain-English explanation: why this vintage passed, which gate was binding, what the DSR/PBO/SPA numbers imply, and (once QE-469 lands) what the CPCV distribution says about out-of-sample confidence.

This is the **lowest-risk** place to introduce agentic AI into the engine and is deliberately sequenced **first** of the two AI tickets: it is strictly read-side, it cannot touch selection, sealing, or any gate, and it establishes the reusable Claude-in-Rust plumbing (auth, HTTP client, typed error handling, `stop_reason` handling) that the brainstormer (QE-472) then reuses. It also pairs with QE-468 — same audience (the human report surface), complementary content (QE-468 makes the *numbers* honest; QE-471 makes them *legible*).

**Engineering reality — read before scoping.**
- **No official Anthropic Rust SDK exists.** The integration is **raw HTTPS** against `POST https://api.anthropic.com/v1/messages` via `reqwest`, `anthropic-version: 2023-06-01` header, `x-api-key` from `ANTHROPIC_API_KEY`. Model **`claude-opus-5`** (current default; `max_tokens` streamed to avoid HTTP timeouts on long output; adaptive thinking is on by default — omit the `thinking` field). Do **not** hand-roll a "Claude SDK for Rust"; a single typed `messages(request) -> Result<Response, LlmError>` function is the whole surface.
- **Off the deterministic core.** The LLM call is **non-deterministic and network-bound** and must never be linked into the deterministic evaluation/seal path or the QE-006 determinism harness. This job runs **offline/batch** and reads an *already-sealed* artefact — it produces prose, never a sealed field.

**Scope / requirements.**
- **New feature-gated crate/module for the LLM client.** Add an `llm` client (e.g. a new `crates/llm` crate, or a module behind an `llm` cargo feature mirroring the existing `http` feature pattern in `crates/ingest`). It exposes a minimal `messages(...)` call over `reqwest`: builds the request body, sends `x-api-key` + `anthropic-version`, **streams** the response, and returns a typed result. **`ANTHROPIC_API_KEY` is read from the environment; never logged, never persisted, never placed in any sealed artefact or committed file.** The feature is **off by default** so the deterministic core never links `reqwest`/TLS.
- **`stop_reason` + error handling, fail-soft.** Handle `stop_reason == "refusal"` (check before reading `content`), `max_tokens`, network/timeout, non-2xx, and rate-limit (`429`, honour `retry-after`) as typed `LlmError` variants. The narrator is **advisory**: any failure returns an error the CLI surfaces plainly — it never blocks, mutates, or invalidates the vintage it was asked to explain.
- **`qe explain <vintage-id>` job.** New `crates/cli/src/jobs/explain.rs` + subcommand. It loads the sealed `VintageContent` (via the existing vintage repository / read path — **read by handle, never recompute**), serialises the seal evidence + research provenance into the prompt, calls `messages(...)`, and prints the generated explanation. Optional `--json` to also emit the raw evidence alongside the prose. A `--model` flag defaults to `claude-opus-5`.
- **Prompt is grounded in persisted evidence only.** The prompt includes the *actual* persisted `SealEvidence` / `ResearchProvenance` fields and the gate thresholds (`DeflationGate` floor, `max_pbo`), so the explanation describes *this* vintage's real numbers. The system prompt states plainly that the model must explain, not re-judge — it may not assert a vintage is good/bad beyond what the gate already decided.
- **No new persisted field, no schema bump.** The generated text is a CLI/report artefact, not part of the content-addressed vintage. `VINTAGE_FORMAT_VERSION` is untouched; no golden moves.

**Out of scope.** Any write to `VintageContent`, `SealEvidence`, or the seal path. Any influence on selection, promotion, or gate thresholds (this reads the gate's decision; it never re-decides). Formula ideation / candidate generation (QE-472). A server SPA surface for the explanation (a follow-up once the CLI job is proven). Persisting or caching LLM output into any sealed artefact.

**Acceptance criteria.**
- `qe explain <vintage-id>` loads a sealed vintage by handle and prints a plain-English explanation grounded in the persisted `SealEvidence` + `ResearchProvenance` fields; `--json` additionally emits the raw evidence.
- The `llm` feature is **off by default**; a default `cargo build`/`cargo test` links neither `reqwest` nor any TLS stack, and the QE-006 determinism harness is unchanged and green.
- `ANTHROPIC_API_KEY` is read from the environment and never appears in logs, output files, or any committed/sealed artefact (assert via a test that scans the job's non-stdout writes).
- All `LlmError` paths (refusal, max_tokens, network, non-2xx, 429) are handled fail-soft: the command reports the error and exits non-zero **without** mutating or invalidating the vintage.
- No `VintageContent` field or `VINTAGE_FORMAT_VERSION` changes; no golden drift.
- A unit test with a **mocked** `messages(...)` (no network) proves the job serialises the correct evidence into the request and renders the response — CI never calls the real API.
