# QE-480 — Make the regime log-return deterministic across architectures (or drop regime_composition from the hash)  *(R5 — panel review 2026-07-31, P1)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: signal (regime) / vintage hash` · `Depends on / relates to: QE-006 (determinism); relates to QE-486 (regime split)`

**Why.** Regime labelling computes a per-bar log return `(p1 / p0).ln()`
(`crates/signal/src/regime.rs:114`) in `f64`. (Path correction: the labeller lives in **`qe-signal`**,
not `qe-ensemble` — the review's `crates/ensemble/src/regime.rs` citation is the QE-127 *consumer*, not
the labeller. `qe-ensemble` imports `label_regimes` from `qe-signal`, see the module docstring at
`crates/signal/src/regime.rs:6`.) Verification narrowed the original claim: the rolling-volatility
`var.sqrt()` (`regime.rs:128`) is IEEE-754 correctly-rounded and the even-length median averaging
`(sorted[mid-1] + sorted[mid]) / 2.0` (`regime.rs:147`) is deterministic — **`ln()` is the sole
non-correctly-rounded, platform-dependent operation** in the path. Its output feeds the rolling vol, the
Calm/Volatile median split, and hence the sealed `regime_composition`, which is **inside the vintage
content hash**. On a knife-edge bar `ln()` can round differently on arm64 vs x86_64, flip Calm↔Volatile,
change the composition tally, and change the **vintage id** — violating the QE-006 reproducibility
invariant the codebase otherwise rigorously protects.

Scope is bounded: `regime_composition` is `Vec::new()` on a plain train
(`crates/cli/src/jobs/train.rs:1025`, the `None` arm) and is only populated on a `--flow` composite run
(`train.rs:1019-1022`, from `f.regime_composition.clone()`), so the divergence bites **only on flow
trains** — latent for non-flow, but a hard reproducibility break where it fires.

**Scope / requirements.**
- **Option A — make the transcendental deterministic.** Compute the regime log-return (and any other
  transcendental in the labeller) in `rust_decimal`, mirroring the existing decimal `powd` pattern
  (`crates/risk/src/slippage.rs:161`, "`u^β` is `rust_decimal`'s `MathematicalOps::powd` … byte-
  reproducible on a pinned toolchain"). The whole `rets` → `vols` → `median` chain then reduces to
  cross-arch-stable arithmetic before the f64 hand-off to the composition tally.
- **Option B — exclude from the hash.** Drop `regime_composition` from the hashed `VintageContent` and
  document it as a **non-reproducible descriptive sidecar** (persisted, but not content-addressed). This
  is the smaller change if the tally is genuinely descriptive-only (see QE-486).
- Pick one and state which; do not leave the f64 `ln()` inside the content hash.

**Out of scope.** The efficiency-ratio / trend axis (price-space, no transcendental). The Calm/Volatile
**full-sample median look-ahead** concern — that is QE-486. The CPCV distribution figures (already routed
through `hash_stable`). Any change to non-flow train output.

**Acceptance criteria.**
- **Either** the regime computation is decimal/deterministic and a cross-arch test shows identical
  labels for a knife-edge series, **or** `regime_composition` is provably excluded from the content hash
  (a test mutates the composition and asserts the vintage id is unchanged).
- A QE-006 determinism test: two runs of a `--flow` train on identical inputs produce **byte-identical
  vintage ids**.
- No behaviour change to non-flow trains (composition stays `Vec::new()`).
- Sealed-schema change (Option B removing a hashed field) ⇒ exactly **one** `VINTAGE_FORMAT_VERSION` bump
  (currently `8`) via the real seal path, goldens regenerated intentionally.
