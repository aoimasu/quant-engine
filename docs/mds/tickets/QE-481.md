# QE-481 — Move the supervisor's `drain_stdout` fs work off the async worker: one persistent append handle + `spawn_blocking` + coalesced `write_meta`  *(R5 — panel review 2026-07-31, P1)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: server (runs supervisor)` · `Depends on / relates to: QE-411 (blocking-in-async removal)`

**Why.** `drain_stdout` (`crates/server/src/runs/manager.rs:1317`) runs inside the `supervise` async task via `tokio::join!` (`manager.rs:790-794`) and is **not** wrapped in `spawn_blocking`. For **every** subprocess stdout line it does synchronous `std::fs::OpenOptions::new().create(true).append(true).open(&log_path)` + `writeln!` (`manager.rs:1329-1335`) — **reopening the file per line** — and on each progress/gen/gate line calls `store.write_meta(meta)` (`manager.rs:1339`, and the flow path `manager.rs:1312`), which is `atomic_write` = `fs::write` + `fs::rename`. This blocks a Tokio runtime worker on synchronous disk I/O for the entire lifetime of a running campaign, starving other tasks under load. This is exactly the pattern QE-411 fixed everywhere else: `create()` moved `init_run` and the discovery-index read-modify-write into `spawn_blocking` while holding `index_lock` across the await (`manager.rs:207-225`, lock at `manager.rs:217`). The QE-411 guard test `handlers_do_no_blocking_std_fs` (`crates/server/src/runs/api.rs:399-414`) scans only `api.rs` and therefore does **not** cover the supervisor path — the regression it was meant to prevent is live in `manager.rs`. Violates the async-non-blocking invariant QE-411 established.

**Scope / requirements.**
- **Open `stdout.log` once per run, not per line.** Acquire a single persistent append handle (`OpenOptions … .append(true).open(store.stdout_path(&meta.id))`) before the `while let … lines.next_line()` loop (`manager.rs:1327`), reuse it for every `writeln!`, and drop it when the loop ends. Remove the per-iteration `open` at `manager.rs:1329-1335`.
- **Run the append + meta persistence off the async worker.** Do the blocking `writeln!` and `write_meta` via `spawn_blocking` (or move the whole drain body into a blocking task fed by an async channel of parsed lines) so no synchronous `std::fs` executes on a runtime worker thread — mirror the QE-411 `spawn_blocking` shape used in `create()` (`manager.rs:207,225`).
- **Coalesce `write_meta`.** Do not persist meta on every line. Throttle to a stage-change / bounded-interval cadence (persist on `stage` transitions and at most once per short interval), so a chatty `gen` stream does not trigger an `atomic_write` (`fs::write`+`fs::rename`) per line. Ensure the **final** terminal state is always flushed.
- **Extend the anti-blocking guard.** Broaden `handlers_do_no_blocking_std_fs` (or add a sibling test) to also scan the supervisor region of `manager.rs` (the `drain_stdout` / `supervise` bodies) for a residual `std::fs::` token, so this path is covered going forward.

**Out of scope.** The QE-454 §13.10 per-run wall-clock deadline / `kill_on_drop` logic wrapping the drain (`manager.rs:786-794`) — preserve it unchanged. `drain_stderr_tail` (the in-memory tail sibling in the same `join!`). The progress-line parsing / `Progress` / `GenSnapshot` semantics (`manager.rs:1336-1364`) — only *where* the I/O runs and *how often* meta is written changes, not what is captured. The discovery-index path already fixed by QE-411.

**Acceptance criteria.**
- The drain loop performs **no** synchronous `std::fs` on a runtime worker (guard test extended to the `manager.rs` supervisor path and green).
- `stdout.log` is opened **once per run**, not once per line (reviewer-checkable: single `open` outside the read loop).
- `write_meta` is coalesced (stage-change / interval), not per line, and the terminal run state is still flushed exactly once — a test asserts the final persisted `meta` matches the terminal state despite throttling.
- Run monitoring output is unchanged: captured `stdout.log` contents and the observable progress/terminal transitions are identical to today for a representative run.
- Server-only change: no QE-006 core, vintage content hash, or `VINTAGE_FORMAT_VERSION` impact.

`Spec ref: docs/reviews/panel-review-2026-07-31.md (finding P2.2, twice-verified). Applies the QE-411 `spawn_blocking` discipline to `drain_stdout` (manager.rs:1317-1339) and extends the guard test (api.rs:399-414) to the supervisor.`
