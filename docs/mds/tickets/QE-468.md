# QE-468 — Report-surface Sharpe honesty: daily aggregation + PSR + autocorrelation haircut + trial-count/DSR on the human report  *(R3 — AFML panel #1)*

> **Status:** Todo — [gap analysis](../../afml-gap-analysis.md#recommendations--adopt-unified-ranked-across-all-four-panels) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R3 (AFML panel)` · `Area: cli / metrics / validation / server` · `Depends on: QE-439 (DSR), QE-467 (persisted seal evidence)`

**Why.** The engine keeps **two** Sharpe numbers and they disagree in rigour. The *selection-path*
Sharpe (DSR/PSR/PBO in `crates/validation`) is careful, per-period, and multiple-testing-aware. The
*reported headline* Sharpe a human reads is not: `metrics::sharpe` annualises a per-bar Sharpe by a
naïve `√ppy` (`crates/cli/src/jobs/metrics.rs:68,78` — `mean / var.sqrt() * periods_per_year.sqrt()`),
called from `crates/cli/src/jobs/backtest.rs:262` with `ppy = periods_per_year(resolution)`
(`backtest.rs:257,366`). At `H1`, `ppy = 8760 ⇒ √ppy ≈ 93.6`; at `M5`, `ppy ≈ 105,120 ⇒ √ppy ≈ 324`.

`√t` scaling assumes IID returns. Crypto perp returns exhibit strong volatility clustering and
non-zero autocorrelation, so `√ppy` scaling **overstates** the annualised figure — and the reported
number carries **no** skew/kurtosis (PSR) haircut and **no** trial-count `N` beside it, even though
`probabilistic_sharpe_ratio` (`crates/validation/src/dsr.rs:39`) and the deflation basis already
exist and are persisted at seal time (QE-467). The book's own warning is explicit — the Sharpe ratio
"relies on returns being IID" and must be reported with PSR and the number of trials (López de Prado,
Ch. 14 pp. 203–205; the "Third Law"). This ticket makes the **reported** statistics as honest as the
**selection** statistics already are. It changes *reporting*, not *selection or gating*.

**Scope / requirements.**
- **Aggregate to a coarse clock before annualising.** In the backtest metrics path
  (`crates/cli/src/jobs/backtest.rs:257-263`), before computing the headline Sharpe/Sortino, resample
  the per-bar net-return series to **daily** buckets (sum of per-bar net log-or-simple returns within
  each UTC day — match the existing `equity_curve` return convention), then annualise the daily
  Sharpe by `√365`. Keep the per-bar series available for the DSR/selection path unchanged. The raw
  per-bar Sharpe may be retained as a secondary/diagnostic field but must **not** be the headline.
- **Apply a Lo (2002) autocorrelation haircut.** Replace the naïve `√q` annualisation factor in the
  aggregated Sharpe with Lo's `√q / √(1 + 2·Σ_{k=1}^{q-1}(1 − k/q)·ρ_k)`, where `ρ_k` are the sample
  autocorrelations of the (daily) return series and `q` is the annualisation horizon in those units.
  Add this as a new pure function in `crates/cli/src/jobs/metrics.rs` (e.g. `sharpe_lo_annualised`)
  with its own unit tests; the existing `sharpe`/`sortino` stay as the per-period primitives.
- **Surface PSR beside every reported Sharpe.** Compute `probabilistic_sharpe_ratio(returns,
  sr_benchmark = 0)` (`crates/validation/src/dsr.rs:39`) on the aggregated series and include it in the
  reported metrics struct and every render surface (CLI backtest output + server report JSON the SPA
  reads). PSR answers "P[true SR > benchmark]" and is the book's mandated companion to SR (p. 205).
- **Emit the tracked trial-count `N` and DSR/PBO onto the human report.** QE-467 persists the seal
  evidence (`dsr`, `pbo`, `spa`, `fdr`, `n_trials`) into the sealed `VintageContent`. Thread those
  persisted fields onto the report/render surface (read the handle, do **not** recompute) so the
  reader sees `SR (daily, Lo-adjusted) · PSR · DSR · PBO · N`. This is literally what satisfies the
  "Third Law" (report every backtest with its trial count) for a human.
- **Label units on every surface.** Every displayed Sharpe must state its clock and adjustment
  (`"SR 1.8 (daily, Lo-adj)"`, not a bare `1.8`) so a per-bar and a daily figure can never be silently
  compared.

**Out of scope.** Any change to the **selection/gating** path — `DeflationGate`, `evaluate_g1`, the
seal predicate, PBO/SPA/FDR thresholds, or `effective_trials`/`gp_trial_basis`. This ticket does not
re-decide any promotion; it only changes what the *report* shows. No new persisted seal field (QE-467
already persists the evidence; this reads it). No CPCV distribution (that is QE-469). No change to the
`equity_curve`/`drawdown`/`cagr` definitions.

**Acceptance criteria.**
- The headline Sharpe on every surface (CLI + server report JSON + SPA) is computed on **daily**-
  aggregated net returns and annualised by the **Lo-adjusted** factor, and is labelled with its clock
  and adjustment.
- A new `metrics::sharpe_lo_annualised` (or equivalent) exists with unit tests covering: (a) zero
  autocorrelation reproduces the naïve `√q` factor to within tolerance; (b) positive autocorrelation
  **lowers** the annualised Sharpe vs naïve; (c) the degenerate/zero-variance case returns 0, not NaN
  (mirroring `sharpe_zero_variance_is_zero_not_nan` at `metrics.rs:200`).
- **PSR** is reported next to every headline Sharpe, computed on the same aggregated series.
- The persisted **DSR, PBO, and trial-count `N`** (from the sealed vintage, QE-467) appear on the
  human report surface, read by handle — no recomputation, no new deflation call.
- A regression test asserts that for a synthetic autocorrelated series the reported annualised Sharpe
  is **strictly below** the current `√ppy` figure (proves the inflation is removed).
- The QE-006 determinism harness stays green; no sealed-artefact hash drift (this is a report-surface
  change, not a content change).
