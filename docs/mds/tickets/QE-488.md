# QE-488 — In `ExprArchive::insert`, replace a same-cell near-duplicate when the offspring is strictly fitter instead of rejecting it before fitness is ever compared  *(R5 — panel review 2026-07-31, P2)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: wfo (gp archive)` · `Depends on / relates to: QE-451 (Phase-1a GP illumination, the opt-in path); relates to QE-450 (grammar)`

**Why.** `ExprArchive::insert` (`crates/wfo/src/gp/archive.rs:105-137`) runs behavioural dedup **first**, before
any fitness comparison: for each existing elite in the target cell,
`if quantised_correlation(&existing.series, &elite.series) > DEDUP_THRESHOLD { return ExprInsert::DedupRejected }`
(`archive.rs:110-114`, `DEDUP_THRESHOLD = 0.95` at `archive.rs:22`). `credit_of(DedupRejected)` then maps to
`ApplicationOutcome::NoImprovement` (`crates/wfo/src/gp/mod.rs:189,193-194`), which down-weights the operator that
produced the offspring (`selector.record(op, &credit_of(outcome))`, `mod.rs:248`). So a **strictly fitter**
offspring that correlates `> 0.95` with a same-cell incumbent — exactly what `local_refine`'s one-step constant/
window nudge produces (`crates/wfo/src/gp/variation.rs:152-155`) — is rejected **regardless of fitness**, and the
exploit operator is penalised for having improved the cell. That is backwards for a MAP-Elites archive: the
standard rule is that a near-duplicate *replaces* its neighbour when fitter. **Verification narrowed the blast
radius:** this is a deliberate diversity rule on the **default-off, opt-in** QE-451 Phase-1a GP path
(`mod.rs:3`; the campaign runner is `illuminate`, `mod.rs:203`), and only **same-cell** near-duplicates are
affected — the cell is `descriptor_for_tree(&elite.tree)` (`archive.rs:106`), so a nudge that shifts the
behavioural descriptor into another cell escapes dedup entirely. Bounded and opt-in, hence P2 — but within that
path it makes the exploit operator strictly counterproductive.

**Scope / requirements.**
- **Apply the standard behavioural-archive replacement rule** in `ExprArchive::insert` (`archive.rs:104-137`):
  when an offspring correlates `> DEDUP_THRESHOLD` with an existing same-cell elite, **replace that elite iff the
  offspring is strictly fitter** (`elite.fitness > existing.fitness`); only return a rejection when the offspring
  is **not better** than its nearest behavioural neighbour. Reuse the existing "displace the worst iff strictly
  better" idiom already present for the full-cell case (`archive.rs:124-136`).
- **Add a credited outcome for the fitter-replacement.** A dedup-driven improvement must not be scored as
  `NoImprovement`: route the "replaced a near-duplicate because strictly fitter" case through an improvement
  outcome in `credit_of` (`mod.rs:189-196`) — e.g. reuse `ExprInsert::ImprovedElite` / `ApplicationOutcome::
  ImprovedElite { gain }` — so the operator is credited, not penalised, for improving the cell.
- **Keep genuine dedup for non-improvements.** An offspring that is a near-duplicate **and not fitter** than its
  neighbour still returns a reject outcome (unchanged diversity protection); cross-cell offspring still bypass
  dedup entirely (`descriptor_for_tree`, `archive.rs:106`).

**Out of scope.** The `default-off` gating of the whole GP stage (`mod.rs:3`) — this ticket does **not** turn the
Phase-1a path on. `quantised_correlation` and `DEDUP_THRESHOLD` (`archive.rs:22,58`) stay as-is. The Deep-Grid
`SUBPOP_SIZE` full-cell replacement logic (`archive.rs:120-136`) except where the new dedup-replace path reuses
its strict-better comparison. Descriptor/cell assignment. Any production (default-on) behaviour surface.

**Acceptance criteria.**
- A test that a `local_refine`-style **+ε-fitness near-duplicate** (correlation `> 0.95` with the same-cell
  incumbent, `elite.fitness > existing.fitness`) **improves its cell** — the incumbent is replaced and the
  outcome credits the operator (not `NoImprovement`); a strictly-**worse** near-duplicate is still rejected.
- A test that **cross-cell** diversity is preserved: an offspring landing in a distinct `ExprCell` is added
  without dedup, exactly as today.
- Determinism: `insert` stays deterministic under the QE-006 harness — same `master_seed` + same samples ⇒
  byte-identical archive and counts (the `illuminate` guarantee, `mod.rs:199-202`); no wall-clock, no unseeded
  RNG, ties broken by lowest index as in the existing worst-elite selection (`archive.rs:125-130`).
- Opt-in QE-451 Phase-1a path only: the `default-off` behaviour surface is unchanged, and the distinct-canonical
  trial ledger (`PoolLineage`) is unaffected — this changes which elite occupies a cell, not how many hypotheses
  are counted.
