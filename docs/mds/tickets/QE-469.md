# QE-469 — CPCV-distributed OOS evidence: replace the single G1 terminal-holdout point estimate with a distribution of held-out Sharpe/DSR  *(R3 — AFML panel #2)*

> **Status:** Todo — [gap analysis](../../afml-gap-analysis.md#recommendations--adopt-unified-ranked-across-all-four-panels) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R3 (AFML panel)` · `Area: validation / wfo / vintage` · `Depends on: QE-113 (purged CV), QE-439 (DSR), QE-467 (persisted seal evidence); pairs with QE-468`

**Why.** The out-of-sample verdict currently rides on **one path**. In-window purged k-fold
(`crates/wfo/src/cv_fitness.rs`) is honestly documented as *in-window CV, not held-out OOS*, and "the
**G1 terminal holdout** … remains the **only true OOS gate** in the pipeline" (`cv_fitness.rs:34-35`).
That is a **single** train/holdout split producing a **single** OOS number. This is precisely the
failure mode Ch. 12 of *Advances in Financial Machine Learning* was written against: a single
walk-forward path is easily overfit and non-representative, and the book prescribes **Combinatorial
Purged CV (CPCV)** — over the `C(N, N/2)` balanced block partitions, generate *many* backtest paths to
obtain a **distribution** of OOS Sharpe rather than one point estimate (Ch. 12.4, p. 163).

The decisive fact from the panel: **the hard part is already built.** The CSCV implementation in
`crates/validation/src/pbo.rs` already splits the time axis into `S` blocks and iterates every
balanced `C(S, S/2)` train/test partition (`pbo.rs:3-5,16-28`), and the purge+embargo primitives
(`crates/wfo/src/cv.rs`, `PurgedKFold`) already produce leak-free splits. CPCV is a reuse-and-emit of
this machinery, not new leakage-control code. This turns the G1 gate from *one number* into a
*confidence interval*, and is the highest-value methodological fix after report honesty (QE-468).

**Scope / requirements.**
- **Add a CPCV path generator over the existing combinatorial split machinery.** Introduce a function
  (in `crates/validation`, sibling to `pbo_cscv`) that, given the block count `S` and group size, walks
  the `C(S, S/2)` balanced partitions and — reusing the **same purge+embargo** as `PurgedKFold`
  (`crates/wfo/src/cv.rs`) — reconstructs, for each partition, the concatenated **held-out** net-of-cost
  return path for the candidate. Output: a set of `N_paths = C(S, S/2) · (S/2)⁻¹`-style backtest paths
  (document the exact path-count formula per López de Prado Ch. 12) each with its own realised return
  series.
- **Reduce the paths to a distribution, not a point.** For the promoted candidate, compute per-path
  Sharpe and per-path DSR, and summarise as a **distribution**: median, IQR / 5th–95th percentile, and
  the fraction of paths with DSR ≥ the existing floor (0.95). This distribution — not a lone terminal
  number — becomes the OOS evidence.
- **Wire it into the seal evidence as the OOS verdict.** Persist the CPCV distribution summary into the
  sealed `VintageContent` seal-evidence block (the QE-467 evidence schema): store the per-path Sharpe
  vector (or its content handle) plus the summary stats, content-addressed. The single terminal-holdout
  figure may be retained as a secondary field but the **promotion-facing OOS evidence is the CPCV
  distribution**.
- **Preserve the fail-closed discipline.** The promotion gate consumes the distribution summary (e.g.
  require the **lower** percentile of held-out DSR, not the mean, to clear the floor). Under-powered /
  too-few-blocks configurations must fail **closed** (reject), never default-accept — mirror the
  existing gate posture in `crates/wfo/src/gp/deflation.rs`.
- **Determinism.** Path generation must be deterministic under the QE-006 harness — the partition
  enumeration order and any per-path seeding derive from the existing `task_rng(master, index)` scheme;
  no wall-clock, no unseeded RNG.

**Out of scope.** Changing the purge/embargo *arithmetic* (reuse `PurgedKFold` as-is). Replacing PBO
(PBO stays the primary overfitting gate; CPCV adds the OOS *distribution* alongside it — they are
complementary, both derived from the same combinatorial splits). Any new bar clock (QE-470). The
report-surface honesty work (QE-468) — though QE-469's distribution should render through the QE-468
surface once both land. Any change to in-window `cv_fitness` selection fitness.

**Acceptance criteria.**
- A CPCV generator exists that reuses the CSCV block-partition enumeration (`pbo.rs`) and the
  `PurgedKFold` purge+embargo (`cv.rs`) to emit **≥ 2** held-out paths (documented path-count formula),
  each with a leak-free concatenated net-of-cost return series.
- A leakage test proves every CPCV held-out path is **window-disjoint** from its own training blocks
  under purge+embargo (mirror the `windows_disjoint` invariant already tested for `PurgedKFold`).
- The promoted vintage's sealed evidence carries a **CPCV OOS distribution** (per-path Sharpe/DSR
  vector + median/IQR/percentile summary), content-addressed, alongside (not replacing) the terminal
  holdout.
- The promotion gate decides on a **percentile of the held-out DSR distribution**, and an
  under-powered configuration (too few blocks / degenerate paths) **fails closed**.
- Deterministic: two runs with identical inputs produce byte-identical CPCV path sets; QE-006 harness
  green.
- Golden/version handling: if the sealed evidence schema changes, exactly one `VINTAGE_FORMAT_VERSION`
  bump via the real seal path, goldens regenerated intentionally, `==` assertion updated (follow the
  QE-467 single-bump discipline).
