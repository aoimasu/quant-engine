# QE-477 — Build the CPCV "OOS" distribution from genuinely held-out returns (or per-split refit), not from the in-sample selection window  *(R5 — panel review 2026-07-31, P1)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: cli (train) / validation / vintage` · `Depends on / relates to: QE-469 (CPCV distribution), QE-479 (purge/embargo load-bearing)`

**Why.** The CPCV distribution branded "out-of-sample" is computed over **in-sample** returns. `crates/cli/src/jobs/train.rs:796` binds `in_sample_returns = combine(&chromosomes, &weights, train_bars, &train_cfg)` — the deployed ensemble's returns over the **train** window it was selected on — while `train.rs:797` separately holds `holdout_returns` over `holdout_bars`. The QE-469 block then feeds the wrong series: `qe_validation::CpcvDistribution::build(&in_sample_returns, …)` at `train.rs:873-874`. Because the candidate is **fixed** — no per-split refit, `crates/validation/src/cpcv.rs:30-33` documents this "already-selected deployed ensemble" — holding out contiguous blocks of the selection data yields in-sample sub-window Sharpes, so `dsr_p05` is optimistically biased. Yet `crates/vintage/src/lib.rs:105-108` labels that summary "the promotion-facing OOS evidence that replaces the single G1 terminal-holdout point estimate." This is an **honesty/label** defect (violates statistical honesty), not a gating hole: the genuine `evaluate_g1` still runs on `holdout_returns` (`train.rs:853`) and is AND-conjoined at `train.rs:896` (`g1.promoted = g1.promoted && cpcv_gate_pass`), so CPCV can only make promotion **stricter**, never bypass the terminal holdout. The mislabel is the harm — a promotion-facing "OOS distribution" that never saw held-out data.

**Scope / requirements.**
- **Feed CPCV genuinely out-of-sample returns.** Change the `CpcvDistribution::build(...)` call at `train.rs:873-883` to build over the frozen `holdout_returns` / `holdout_bars` (`train.rs:797`), so every held-out configuration's Sharpe/DSR is measured on data outside the selection window. Thread `schema.max_lookback()` / `DEFAULT_LABEL_HORIZON` unchanged.
- **OR make the multiplicity load-bearing via per-split refit.** Alternatively, refit/re-select the ensemble per combinatorial split so each held-out block is OOS relative to a model trained only on the complementary blocks — the honest CPCV of López de Prado Ch. 12. This is the path that also makes QE-479's purge/embargo actually do work; if chosen, coordinate the two.
- **Stop labelling an in-sample sub-window distribution "out-of-sample."** Whichever fix lands, the `qe_vintage` doc/field wording (`lib.rs:105-108`) must match the data the distribution was actually computed on.
- Preserve the existing fail-closed conjunction at `train.rs:896` and the `CpcvGate` lower-percentile decision (`cpcv.rs:305-310`) exactly — this ticket changes the **input series**, not the gate arithmetic.

**Out of scope.** The purge/embargo arithmetic in `cpcv.rs` and its cross-crate `PurgedKFold` equivalence (QE-479 owns the "load-bearing" question). PBO / `CSCV_BLOCKS` (QE-478). The G1 terminal-holdout gate itself (`evaluate_g1`) and the `DEFAULT_CPCV_BLOCKS = 6` geometry.

**Acceptance criteria.**
- The distribution branded "OOS" is computed on genuinely held-out data (`holdout_returns`) **or** per-split refit; a test asserts the series passed to `CpcvDistribution::build` is not the train-window `in_sample_returns`.
- The `qe_vintage::SealEvidence` CPCV field/doc wording matches the data source (no "out-of-sample" claim over a selection-window series).
- Fail-closed conjunction preserved: an under-powered / `build → Err` config still forces `g1.promoted = false` (`train.rs:896`).
- Determinism preserved (QE-006): two runs with identical inputs produce byte-identical CPCV path sets and summaries; harness green.
- If the sealed evidence schema changes, exactly one `VINTAGE_FORMAT_VERSION` bump via the real seal path with goldens regenerated intentionally (QE-467 single-bump discipline).
