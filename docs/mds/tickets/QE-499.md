# QE-499 — GP evolve → G1 vintage bridge: let evolved `Expr` formulas become gate-evaluated candidate strategies  *(R6 — fleet diagnosis 2026-08-01, LARGE / design-first / evidence-gated)*

> **Status:** Phase A + B done (design→review→implement→verify→honesty-review→fix→re-verify); Phase C (evolve→pool→train re-hunt) next — [design doc](../architecture/qe-499-gp-vintage-bridge-design.md) · [G1-hunt diagnosis](../../reviews/) · [backlog index](../../backlog.md)

`Phase: Review R6 (real-data edge experiment)` · `Area: wfo (gp) / cli (train) / vintage / gate / formula-pool / governance` · `Depends on / relates to: QE-451 (GP evolve engine + trial ledger), QE-454 (production-seal governance), QE-134 (G1 gate), QE-469 (CPCV), QE-491 (objective); GATED BY QE-497 (richer factors) + QE-498 (more symbols)`

**Why.** The G1-hunt diagnosis identified **strategy representation** as the deeper binding constraint: the fixed *k*-of-4 threshold grammar over ~18 TA indicators has no deflation-surviving edge on liquid majors. The `evolve` GP path evolves richer `Expr` formula trees — but today a sealed formula **pool never mints a vintage**: the pool→train→G1 bridge is **deliberately unbuilt and fail-closed** ("production sealing stays fail-closed by design until per-formula `gate_evidence` is wired into the pipeline"), and there is no code path from an evolved formula into a G1-evaluated candidate (confirmed: only an empty-pool vintage exists). This ticket builds that bridge so evolved formulas can be honestly evaluated by the **unmodified** G1 gate.

**Why this is design-first / large / gated (read before touching code).** This is the single most honesty-critical build in the engine: it is the path by which **AI/GP-generated strategies could become production-sealed**. Auto-generating it risks exactly the false-discovery inflation the whole engine exists to prevent. It touches the DSR/PBO/CPCV honesty machinery (QE-134/469), the trial ledger (every evolved candidate MUST count toward the deflation basis — QE-451/472), the search⟂portfolio⟂live firewall (QE-132), and production-seal governance (QE-454). It must NOT be batched with the routine builds and must NOT be auto-implemented by a fleet. It is also **evidence-gated**: build it only after QE-497/498 re-hunt shows whether richer *factors* alone move DSR/OOS — if they do, a cheaper path may exist; if they don't, the representation lever (this ticket) is the justified investment.

**Scope / requirements (to be refined in a dedicated design doc before implementation).**
- A path for evolved `Expr` formulas from a sealed pool to enter a train run as candidate strategies producing a G1-evaluated vintage — with **the unmodified gate** and **per-formula `gate_evidence`** wired so the false-discovery basis is honest (every distinct canonical evolved formula counts toward `gp_trial_basis` / `effective_trials`).
- Preserve every invariant: QE-132 firewall (no live←search edge), QE-454 fail-closed production seal, QE-006 determinism, QE-476 write-but-mark. No gate/threshold weakening.
- A leakage/honesty proof: a batch of K distinct evolved candidates increases the trial basis by exactly K, and a candidate cannot reach the gate uncounted.

**Out of scope.** Any change to the G1 thresholds or the deflation math. Live order submission. This ticket's *implementation* until the gate above is met.

**Acceptance criteria (high-level; expand in the design doc).**
- A design doc (`docs/architecture/qe-499-*.md`) precedes any implementation, reviewed for the honesty/firewall/governance implications.
- Evolved formulas can produce a vintage the **unmodified** G1 gate evaluates; every evolved candidate is counted in the deflation basis (asserted by test).
- Firewall + fail-closed governance + determinism tests stay green; no gate weakened.
- Sealed-schema change (if any) ⇒ single `VINTAGE_FORMAT_VERSION` bump with goldens regenerated intentionally.
