# QE-493 — Enforce the sealed `is_promoted()` verdict at the vintage-selection boundary (make the QE-476 flag load-bearing)  *(R5 — panel review 2026-07-31, follow-up to QE-476)*

> **Status:** Todo — [PR #182 review R2.3](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md)

`Phase: Review R5 (panel review — PR #182 follow-up)` · `Area: server / cli / vintage` · `Depends on / relates to: QE-476 (write-but-mark promoted verdict + fail-closed is_promoted())`

**Why.** QE-476 makes a sealed vintage carry its G1 promotion verdict (`SealEvidence.promotion`, with `is_promoted()` fail-closed on `None`) and writes a **G1-failed vintage marked `promoted = false`** ("write-but-mark", the resolved product decision). But PR#182 review **R2.3** confirmed the mark is currently **legible, not load-bearing**: `SealEvidence::is_promoted()` (`crates/vintage/src/lib.rs:157`) has **no production consumer** — nothing at a vintage load / backtest-select / deploy-select boundary refuses a non-promoted (or unmarked) vintage. So the write-but-mark safety property only holds if downstream code *chooses* to read the flag, and today none does. The credibility guarantee ("a sealed vintage you deploy passed its gate") is only completed when a boundary enforces it.

**Scope / requirements.**
- **Identify the selection boundaries.** Where a vintage is chosen for a *consequential* action — the backtest job's `--vintage` load (`crates/cli/src/jobs/backtest.rs`), the server's vintage listing/selection surface it feeds to backtests (`crates/server/src/…` vintage read/select), and any future deploy-select path.
- **Enforce fail-closed.** At each boundary, refuse a vintage whose `seal_evidence.is_promoted()` is false (or absent ⇒ not promoted), with a named error — mirroring the governance seal's fail-closed posture. A backtest *of* a non-promoted vintage for **research/inspection** may be explicitly allowed via an opt-in flag (e.g. `--allow-unpromoted`, loudly labelled), but the **default** must refuse, so a failed vintage cannot be silently treated as deployable.
- **Keep write-but-mark intact.** Do not stop writing failed vintages (QE-476's decision) — only stop *selecting* them by default. Negative-result lineage is preserved on disk; enforcement is at consumption.

**Out of scope.** The seal/write side (QE-476, done). The G1 gate arithmetic. Live order submission (none exists). Any `VINTAGE_FORMAT_VERSION` change — the field already exists.

**Acceptance criteria.**
- A test that selecting a `promoted = false` (and separately, an unmarked/`None`) vintage at the default boundary is **refused** with a named error; a promoted vintage is accepted unchanged.
- The research opt-in (if added) allows the refused case only when explicitly set, and the allowance is logged/labelled.
- No regression to promoted-vintage backtests; no seal-side behaviour change.
