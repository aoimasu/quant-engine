# QE-479 — Stop advertising "leak-free / purged" for the fixed-candidate CPCV distribution, or make purge/embargo load-bearing via per-split refit  *(R5 — panel review 2026-07-31, P1)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: validation (cpcv)` · `Depends on / relates to: QE-477 (CPCV OOS input / per-split refit)`

**Why.** For the fixed candidate, CPCV's purge/embargo is a **no-op on the produced distribution**. `CpcvPath::returns()` (`crates/validation/src/cpcv.rs:121-131`) iterates **only** `self.test` — `for r in &self.test { for i in r.clone() { … candidate.get(i) … } }` — and never touches `self.train`. The purge+embargo work happens entirely in building `self.train` (`cpcv.rs:169-178`), which the reducer that computes the Sharpe/DSR vectors never reads. Because the candidate is a fixed, already-selected ensemble with no per-split refit (`cpcv.rs:30-33`), the held-out returns are candidate-fixed and the "leak-free / purged" property has **zero** effect on the distribution the gate consumes. Meanwhile the module docstring (`cpcv.rs:5-9,15-20`) and the `qe_vintage` seal wording advertise a "leak-free" purged distribution. VERIFICATION (twice): the purge machinery is **not** literally dead — `CpcvPath::windows_disjoint` (`cpcv.rs:109-116`) and its `cpcv_paths_are_window_disjoint_under_purge_embargo` test (`cpcv.rs:355-382`), plus the cross-crate `PurgedKFold` equivalence, exercise it — so "never consumed" holds for the **reducer path**, not the whole module. This is a documentation/over-reach defect on the sealed evidence surface (violates statistical honesty), tightly coupled to QE-477. Low blast radius, but the sealed narrative currently contradicts the code.

**Scope / requirements.** Pick **one** honest story:
- **(A) Drop the over-claim.** Since `returns()` (`cpcv.rs:121-131`) consumes only `self.test`, remove the "leak-free / purged" advertisement for the fixed-candidate distribution from the module docstring (`cpcv.rs:5-20`) and the `qe_vintage::SealEvidence` CPCV wording. State plainly that the fixed-candidate distribution is taken over the `C(S, S/2)` held-out **configurations** of an already-selected ensemble, and that purge/embargo geometry is retained for the equivalence invariant, not because it changes the reduced series. Consider dropping the unused `train` construction from the fixed-candidate path if nothing else reads it.
- **(B) Make it load-bearing.** Refit/re-select per combinatorial split so each held-out block's return comes from a model trained **only** on its complementary (purged+embargoed) `self.train` blocks — then `self.train` is genuinely consumed and "leak-free / purged" becomes true. This couples directly to QE-477's per-split-refit option; do them together if this path is chosen.

**Out of scope.** The purge/embargo **arithmetic** itself (`cpcv.rs:160-178`) and the `PurgedKFold` cross-crate equivalence test — those stay as the pinned geometry. PBO / `CSCV_BLOCKS` (QE-478). The `CpcvGate` decision logic (`cpcv.rs:302-311`).

**Acceptance criteria.**
- The "leak-free / purged" claim is **either** removed for the fixed-candidate distribution (docstring + seal wording match the reducer that reads only `self.test`) **or** made genuinely load-bearing via per-split refit, with a leakage test proving each held-out path's returns derive from training blocks that are window-disjoint from it (extend the existing `windows_disjoint` coverage at `cpcv.rs:355-382`).
- No silent contradiction remains between any docstring/seal-field text and behaviour — a reviewer can read `cpcv.rs` and the vintage evidence doc and find one consistent story.
- Determinism preserved (QE-006): path geometry stays RNG-free; two runs byte-identical.
- If the sealed evidence schema/wording changes the hashed content, exactly one `VINTAGE_FORMAT_VERSION` bump with goldens regenerated intentionally (QE-467 single-bump discipline).
