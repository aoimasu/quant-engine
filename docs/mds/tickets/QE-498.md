# QE-498 — Expand the point-in-time universe to more liquid perps for wider per-symbol edge search  *(R6 — fleet diagnosis 2026-08-01, P2)*

> **Status:** Todo — [G1-hunt diagnosis](../../reviews/) · [backlog index](../../backlog.md)

`Phase: Review R6 (real-data edge experiment)` · `Area: config / cli (ingest)` · `Depends on / relates to: QE-012 (point-in-time universe), QE-497 (richer factors), QE-495 (funding join)`

**Why.** The edge hunt ran only BTCUSDT/ETHUSDT. Training is **single-instrument** (`crates/cli/src/lib.rs:139` — trains over `instruments.first()`), so there is no cross-sectional signal; but more liquid perps give more **independent markets** to search for a deflation-surviving edge — a different market may hold a directional/positioning edge the two majors do not. This is the cheap, runnable half of the edge experiment.

**Scope / requirements.**
- Add a curated set of liquid USDT perps to the `[[universe]]` table with their **real Binance-futures listing dates** (point-in-time correctness — QE-012): e.g. SOLUSDT, BNBUSDT, XRPUSDT, ADAUSDT, DOGEUSDT, AVAXUSDT (pick 4–6 with long, deep history). Provide it as a config variant (e.g. `config-universe.toml`) so the default `config.example.toml` universe stays BTC/ETH.
- Verify each new symbol ingests bars + funding (+ premium/OI once QE-497 lands) with correct point-in-time windows.
- **Document honestly:** training remains single-instrument, so this enables N independent per-symbol hunts, **not** cross-sectional signal. A cross-sectional / multi-instrument training mode is explicitly a separate, larger ticket.

**Out of scope.** A multi-instrument (cross-sectional) training mode. Delisting handling beyond what QE-012 already does. Any gate change. Running the hunt itself (that follows once the data lands).

**Acceptance criteria.**
- The universe config variant resolves + validates (QE-012 point-in-time), and `qe ingest` populates each new symbol over its listed window with correct provenance.
- Listing dates are the real Binance-futures ones (no survivorship/pre-listing bleakage — a bar before `listed` is never scanned).
- A note in the ticket/report records that training is single-instrument (per-symbol hunts, not cross-sectional).
- No change to the default BTC/ETH config or any existing golden.
