# QE-476 — Seal the G1 promotion verdict into the hashed evidence and gate the vintage write on it  *(R5 — panel review 2026-07-31, P0)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: vintage / cli (train seal)` · `Depends on / relates to: QE-467 (persisted seal evidence); relates to QE-482 (hash-stable evidence)`

**Why.** The seal neither persists nor enforces the G1 verdict. In the train job the G1 decision is
evaluated at `crates/cli/src/jobs/train.rs:853` (`evaluate_g1(..)`) but there is **no branch on
`g1.promoted`** before `Vintage::seal(content)?` (`train.rs:1065`) and the subsequent
`VintageRepository::new(..).write(&vintage)` (`train.rs:1067`) — a **G1-FAILED candidate is still
content-hashed and written** to the vintages dir. `SealEvidence` (`crates/vintage/src/lib.rs:74`) carries
raw DSR/PBO/SPA/turnover/capacity figures but **no `promoted: bool` flag and no per-criterion
thresholds**, so later drift of a threshold constant silently re-classifies an already-sealed artifact:
the same figures now read as pass where they were fail (or vice versa), and the sealed artifact cannot
say which it was. This strikes at the engine's core promise that **sealed = gate-passed, trustworthy.**

Verification note (honest narrowing): the verdict **is** recorded at run time in `TrainResultDoc.g1`
(`train.rs:491-492`, a `G1Decision { promoted, criteria }` from `crates/gate/src/lib.rs:115-122`), so
promotion is auditable **from the run doc**. The exposure is specifically to any downstream selector that
reads **only the content-hashed vintage** and cannot tell pass from fail — the run doc is a separate,
non-content-addressed artefact.

**Scope / requirements.**
- **Seal the verdict into the hashed evidence.** Add the `G1Decision` (or an equivalent) into
  `SealEvidence` so the hashed content carries the `promoted` flag **plus each criterion's
  name/value/threshold** — `CriterionResult { name, passed, value, threshold }` already exists
  (`crates/gate/src/lib.rs:101-109`). The artifact becomes self-describing: a drifted threshold constant
  cannot re-classify it because the threshold it was judged against is frozen in the hash.
- **Gate the vintage write on the verdict.** Branch on `g1.promoted` at the seal/write site
  (`train.rs:1065-1067`) per the chosen policy below.
- **HUMAN DECISION REQUIRED (see review §6):** should a G1-failed candidate be **un-writable** (hard
  fail-closed, no artifact), or **written-but-marked** non-promotable (preserving negative-result
  lineage for research)? **Decide before implementing** — the two policies imply different write-site
  logic and different downstream-selector contracts.

**Out of scope.** The G1 criteria/thresholds themselves and `evaluate_g1` (owned by `qe-gate`). The
`TrainResultDoc.g1` run-doc field (it stays; this adds the *content-hashed* mirror). The CPCV OOS
distribution (QE-469). The hash-stable precision enforcement (QE-482), though the new verdict figures
must obey it.

**Acceptance criteria.**
- A sealed vintage carries an **unambiguous, content-hashed promotion verdict + per-criterion
  thresholds**; a test reads a sealed artifact and recovers `promoted` and each criterion's threshold
  without the run doc.
- A test proves a **drifted threshold constant does NOT change** an already-sealed artifact's recorded
  verdict (the threshold is read from the hash, not re-derived).
- A G1-failed candidate is **either not written or durably marked non-promotable**, matching the chosen
  policy; a test exercises the failed-candidate path end-to-end.
- Sealed-schema change ⇒ exactly **one** `VINTAGE_FORMAT_VERSION` bump (currently `8`, `lib.rs:55`) via
  the real seal path, goldens regenerated intentionally (QE-467 single-bump discipline). Determinism:
  two same-seed runs seal byte-identical ids (QE-006 harness green).
