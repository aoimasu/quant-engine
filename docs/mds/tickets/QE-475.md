# QE-475 — Put the ensemble objective's return, tail, and correlation terms on a common scale (or recalibrate `corr_weight`) so DE selection is not a pure decorrelation search  *(R5 — panel review 2026-07-31, P0)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: ensemble (objective)` · `Depends on / relates to: needs a human intent decision (review §6); relates to QE-115 (unit-weight choice), QE-430 (deflation)`

**Why.** `objective_weighted` (`crates/ensemble/src/objective.rs:462`) returns
`mean + cfg.tail_weight * tail - cfg.corr_weight * corr` (`objective.rs:482`). Here `mean` is
`combined.iter().sum::<f64>() / combined.len()` of the members' per-bar net-of-cost returns
(`objective.rs:472-476`) — O(1e-4..1e-3) per bar; `tail` is CVaR on the same series (`objective.rs:477`),
the same scale; but `corr` is `pairwise_corr_penalty(...).value ∈ [0,1]` (`objective.rs:481`).
`ObjectiveConfig::with_defaults()` sets `tail_weight = 1.0, corr_weight = 1.0` (`objective.rs:442-443`),
and this is the config the production train job uses (`SearchConfig::default → ObjectiveConfig::with_defaults`,
`objective.rs:449-453`). So a realistic member correlation of ~0.3 subtracts **0.3** from an objective whose
entire return+tail contribution is O(1e-3): the correlation term is two-to-three orders of magnitude larger
than everything else, and the DE selection is **effectively a pure decorrelation search**. That directly
contradicts the module docstring — *"rewards mean growth, penalises the left tail, and explicitly penalises
return correlation"* (`objective.rs:1-4`) — which reads as a balanced trade-off, not a decorrelation-dominated
one. This is live in **every sealed vintage's** ensemble membership selection. The unit weight is documented as
a deliberate QE-115 choice, but nothing in the code or docs addresses the **scale mismatch** between a `[0,1]`
penalty and O(1e-3) returns. This violates statistical honesty: the objective does not do what it says.

**Scope / requirements.**
- **This is a HUMAN-INTENT decision first (review §6).** Either (a) the balanced trade-off in the docstring is
  the intent — then normalise the terms to a common scale, **or** (b) decorrelation-first is the deliberate
  house view — then the docstring/comment is what is wrong and must be corrected. Do not silently change the
  default: `objective_weighted` drives sealed history, so any behavioural change is a deliberate rebaseline.
- **If (a) — rescale to a common footing.** Express the return and CVaR terms per-unit-risk, **or** scale the
  correlation penalty by a return-magnitude factor, **or** recalibrate the default `corr_weight` to the return
  scale (~1e-3), inside `ObjectiveConfig::with_defaults()` (`objective.rs:439-446`). Keep `pairwise_corr_penalty`
  and the QE-430 deflation untouched (the penalty *value* is correct; only its *weight relative to returns* is
  wrong). Document the intended trade-off next to the new constant.
- **If (b) — fix the documentation, not the weights.** Correct the `objective.rs:1-4` docstring and the
  `objective_weighted` doc-comment (`objective.rs:455-460`) to state that selection is decorrelation-dominated
  by design, and add a test that **locks** that intended behaviour so a future "balance" refactor is caught.

**Out of scope.** The QE-430 `CorrDeflation` machinery and `pairwise_corr_penalty` arithmetic (correct as-is —
this is a *weighting*, not a *penalty-value*, defect). The capacity-capped `Weighting` path (QE-438). The
leave-one-out floor. PBO/DSR gates. Any schema owned by the seal tickets.

**Acceptance criteria.**
- A test on a **realistic-scale pool** (per-bar returns ~1e-3, member correlations 0.3–0.7) asserting the
  intended behaviour: under intent (a), a materially higher-mean *correlated* ensemble can be **preferred** over
  a near-zero-mean *decorrelated* one; under intent (b), a docstring correction plus a test that **locks** the
  decorrelation-first ordering (the current AC `correlated_strategies_are_penalised...`, `objective.rs:648-670`,
  must still hold and is now the documented intent).
- Determinism: the change touches only weighting/constants or docs, not the QE-006 core enumeration or content
  hash; two runs with identical inputs stay byte-identical.
- Any change to selection output is a **deliberate golden rebaseline**: goldens regenerated intentionally, the
  `==` assertion updated, and `VINTAGE_FORMAT_VERSION` bumped exactly once via the real seal path if the sealed
  ensemble membership changes.
