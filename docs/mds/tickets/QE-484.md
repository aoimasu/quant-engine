# QE-484 — Truncate each pair to its common prefix inside `pairwise_corr_penalty` so a differing-length pair is not silently scored as uncorrelated  *(R5 — panel review 2026-07-31, P2)*

> **Status:** Todo — [panel review](../../reviews/panel-review-2026-07-31.md) · [backlog index](../../backlog.md) · [spec](../../specs.md)

`Phase: Review R5 (panel review)` · `Area: ensemble (objective)` · `Depends on / relates to: relates to QE-451 (Phase-1b provenance penalty, the unguarded caller); QE-430 (deflation)`

**Why.** `pearson` returns `0.0` when the two series differ in length — `if n == 0 || n != b.len() { return 0.0; }`
(`crates/ensemble/src/objective.rs:56-59`). In `pairwise_corr_penalty` (`objective.rs:165-187`) each pair
computes the deflation sample size `let n = si.len().min(sj.len())` (`objective.rs:170`) but passes the
**untruncated** `si`/`sj` straight to `pearson` (`objective.rs:171`). So any pair whose members differ in length
scores `pearson = 0` (treated as *uncorrelated*) while `effective_n` is nonetheless recorded as the min length
(`objective.rs:173`) — the recorded sample size and the correlation are computed over different point sets, and a
genuinely correlated pair silently contributes nothing to the penalty. The maintainers already know this trap: the
server leaderboard caller pre-aligns to `min_len` with the explicit comment *"since `pearson` returns 0 for
unequal-length series"* (`crates/server/src/read.rs:493-503`). But `provenance_aware_penalty` (`objective.rs:269`)
feeds `cluster_mean_series` output (`objective.rs:276-277`) straight in **unguarded**, and each cluster is
truncated to *its own* shortest member (`objective.rs:216-217`) — so clusters can legitimately differ in length,
and the leave-one-provenance-out floor can collapse to 0 on real correlation. This violates fail-closed: a
correlation penalty that should *raise* the score silently reads as *no correlation*. **Latent** today — the
production ensemble path is equal-length, and `provenance_aware_penalty` (QE-451 Phase-1b) has no production caller
yet — but the fix belongs at the primitive, not each caller.

**Scope / requirements.**
- **Truncate to the common prefix inside `pairwise_corr_penalty`** before calling `pearson`
  (`objective.rs:170-171`): compute `let n = si.len().min(sj.len())` (already present) and pass `&si[..n]`,
  `&sj[..n]` to `pearson`, so the correlation and its recorded `effective_n` rest on the **same** points. (An
  equivalent fix — making `pearson` itself correlate over the common prefix — is acceptable, but the caller-side
  slice keeps `pearson`'s equal-length contract intact and is the smaller blast radius.)
- **Preserve every existing invariant:** the `< 2` series → `{0.0, 0}` early return (`objective.rs:176-180`), the
  `max(deflate(r), 0)` floor on negative correlation (`objective.rs:171`), and the QE-430 `deflate_r` deflation on
  the same `n` all stay byte-identical for equal-length inputs.

**Out of scope.** The QE-430 deflation modes and `min_significant_r`. `cluster_mean_series`' own per-cluster
truncation (`objective.rs:206-228`) — that is correct; the bug is only that the *penalty* over those clusters must
align each pair. The server `read.rs` pre-alignment (`read.rs:495-503`) may stay as-is (harmless once the primitive
is fixed) or be simplified in a follow-up — do not remove it in this ticket. No gate/threshold/schema change.

**Acceptance criteria.**
- A unit test with **two genuinely correlated, unequal-length** series asserting a **nonzero** penalty (today it
  returns 0): e.g. a length-N series and a correlated length-(N−k) prefix-shifted series score `> 0`, and
  `effective_n` equals the common length — proving correlation and sample size now agree.
- The **equal-length production path is byte-unchanged**: every existing `pairwise_corr_penalty` /
  `positive_mean_pairwise_corr` / `objective` test (`objective.rs:598-821`) passes unmodified, and the
  `effective_n` uneven-length test (`objective.rs:788-805`) still records the smaller sample.
- Determinism: pure `f64` slice truncation, no RNG, no wall-clock — the QE-006 core and content hash are
  untouched; two runs stay byte-identical. No golden/`VINTAGE_FORMAT_VERSION` change (the equal-length sealed path
  does not move).
